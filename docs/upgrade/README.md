## Updating progress

Tasks are Markdown checkboxes in the sprint files: `[ ]` not started · `[~]` in progress · `[x]` done.
Change them **in the same pull request as the code**, using the tool:

```bash
node docs/upgrade/tools/status.mjs next          # what to do next
node docs/upgrade/tools/status.mjs start S1-03   # mark in progress
node docs/upgrade/tools/status.mjs done  S1-03   # mark done and refresh the table above
node docs/upgrade/tools/status.mjs               # just refresh the table
```

## Conventions

- **Task ids** `S<sprint>-<nn>`; findings `PAY-n`, `SEC-n`, `STR-n`; decisions `D<n>`; proposal gaps `G<n>`; release gates `R1–R4`.
- **Sizes:** S ≈ ½ day, M ≈ 1–2 days, L ≈ 3+ days of focused work. These are planning estimates, not commitments; the table shows ideal dev-days, not calendar time.
- Commit and PR titles start with the task id: `S1-03: add fulfilCheckoutSession`.
- Evidence for anything proven in Stripe test mode goes in `evidence/<sprint>.md`.
- Decisions are recorded in the decision log and referenced by id.

## Important facts for anyone continuing this work

- Next.js is **16.2.1**; `AGENTS.md` says its APIs differ from older versions. Read `node_modules/next/dist/docs/` before using routing, caching, metadata or request-interception features.
- The Figma file title says "Galleroo"; the product name used in the UI and proposal is **PhotoDrive** (D1).
- Prices in the Figma mock-up are samples; real plans come from the admin back office.
- The audit was done by reading code; it has **not** been compared with live Stripe, Sentry or Firestore data. S1/S2 start by proving PAY-1/PAY-2 and PAY-7 with data.
