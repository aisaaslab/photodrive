customers are affected is the S2 back-fill report (PAY-7).

## S1-06 · PAY-1 fixed behind BILLING_FULFIL_V2 (2026-11-25)

`tests/billing/current-behaviour.emu.test.ts`: the PAY-1 test no longer uses `it.fails`; with
`BILLING_FULFIL_V2=1` a lapsed customer who bought the same plan last month now gets a new Checkout
URL and Stripe history is never queried. The flag-off test still pins the old `{ alreadyPaid: true }`
response, so deploying with the flag off changes nothing. `tests/billing/checkout-v2.emu.test.ts`
covers session parameters (`client_reference_id`, `metadata.env`), the idempotency key, active
customers buying again and the unchanged flag-off request.

The new checkout behaviour is gated on the same flag as the webhook and verify route on purpose:
letting active customers pay while the OLD fulfilment path is live would charge them without
extending access (PAY-2). All three switch together.

  with no purchasable plan they show no price (subscribe/new-gallery: existing error text, buy button disabled).

**Deploy order matters (live shop):** before this code reaches production, run the dry run against
production and show the output to the owner:

```bash
npx tsx --env-file=.env.local scripts/migrations/seed-default-plan.ts          # dry run
npx tsx --env-file=.env.local scripts/migrations/seed-default-plan.ts --apply  # only after approval
```

If production already has plans (likely, the back office manages them) the script does nothing and
no action is needed. If it has none, apply the seed first, otherwise nobody can buy after the deploy.

## S1-08 · subscribe page for active users (implemented, awaiting copy review and staging run)

Behaviour (all gated on `BILLING_FULFIL_V2` through `canRenewEarly` from `/api/user/subscription`,
so production behaviour does not change until the flag is on):

- Flag off: active users are redirected to the dashboard, as today.
- Flag on: an active user sees the subscribe page with "Your access runs until <date>." and
  "If you renew now, your access extends to <date>." (computed with the same `computeExpiry` as the
  server), and the button reads "Renew with card →". A lapsed user sees "Your access ended on <date>."
  Admins and lifetime accounts are still sent to the dashboard (nothing to buy).
- Plans unavailable: error text, no price, no buy button (from S1-07). The account-page button no
  longer says "$99/year".
