# S3 evidence

## S3-01 · shared rate limiter (2026-11-25, SEC-2)

`lib/server/rate-limit.ts`. Nothing uses it yet: the routes are moved over in S3-05 (password lockout), S3-06 (contact and
selection-submit), S3-07 (demo limit) and S3-02/S3-04 (media). No new package: Upstash Redis is used through its REST API (decision D6).

- **Stores:** `UpstashStore` (production/staging; sends one atomic `/multi-exec` request per call: `INCR`, `EXPIRE … NX`, `PTTL`) and
  `MemoryStore` (local development and tests; bounded size). `getRateLimiter()` picks Upstash when `UPSTASH_REDIS_REST_URL` and
  `UPSTASH_REDIS_REST_TOKEN` are set, otherwise memory, and logs a warning once in production because memory limits are per
  server instance (the original SEC-2 defect).
- **`limit({ name, id, limit, windowSec })`:** fixed window starting at the first call; returns `allowed`, `remaining`, `retryAfterSec`.
  `rateLimitHeaders()` builds `RateLimit-*` and `Retry-After`.
- **Lockout** for password-style secrets: `isLocked` (check first), `recordFailure` (default 5 failures in 10 min lock for 15 min),
  `reset` (a correct secret clears the failure count but never lifts an active lock).
- **Privacy:** identifiers are hashed (`sha256`, optional `RATE_LIMIT_SALT`), so no raw IP is ever a Redis key; tested.
- **Client IP:** `clientIp()` prefers `x-vercel-forwarded-for` then `x-real-ip` (set by the platform, not forgeable by the client);
  the first `x-forwarded-for` entry is only a local-development fallback.
- **Failure mode:** if the store is unreachable the limiter fails **open** (the request goes through and an error is logged) so a Redis
  outage cannot take the site down; `failClosed: true` is available where denying is safer.

Tests: `tests/rate-limit.test.ts` (20). The Upstash tests run against an in-process fake server that speaks the same REST protocol, and
show: the exact commands and `Authorization` header sent; **limits hold across two separate limiter instances sharing the store**; a
lockout set by one instance is seen by the other; windows expire; HTTP errors, command errors and timeouts fail open (or closed on request).

**Needed for production:** create an Upstash Redis database and set the two environment variables in Vercel (D6). Until then limits stay
per instance. Not yet exercised against a real Upstash database (no credentials in this session).
