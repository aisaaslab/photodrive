## S5-04 · one shared auth layer and a `route()` wrapper (2026-11-26, STR-2)

- **`lib/server/auth.ts`** is now the only place in the app that calls `verifyIdToken`: `verifyBearer(req)` (the user or null, never throws; for routes where signing in is optional), `requireUser(req)` and `requireAdmin(req)` (a result you return from on failure: 401 `{ error: "Unauthorized" }`, or 403 for a signed-in non-admin), and `isAdmin(uid)`.
  The `Authorization` header is parsed strictly (`Bearer <token>`, scheme case-insensitive); before, anything with `Bearer ` stripped out of it counted, including a bare token.
- **The nine route-level copies are gone** (`user/delete`, `user/subscription`, `user/language`, `galleries`, `galleries/[id]`, `galleries/[id]/cover`, `galleries/[id]/photos`, `stripe/checkout`, `stripe/verify`), plus the optional-token copy in the selection route and the one in `lib/server/photo-access.ts`.
  `lib/firebase/admin-guard.ts` (`getUidFromRequest`, `isAdmin`, used by the other admin and user routes and mocked by several tests) is now a thin delegate, so those files did not need to change.
  **Done when: `grep -rn verifyIdToken app lib` finds exactly one line, in `lib/server/auth.ts`.**
- **`route(scope, handler)`** in `lib/server/http.ts`: wraps a handler so an unexpected error is logged (JSON line with scope and request id) and answered as a plain `{ error: "Internal error" }` 500, never a stack trace. Applied to all handlers of those ten route files. Handlers keep returning their own 400/401/404 as before.
  Request parsing stays with `parseJson` (S3-09) and auth with `requireUser`, rather than being hidden inside the wrapper, so each route reads top to bottom. The language route also moved to `parseJson`. Error monitoring (Sentry) hooks in at `route()` once S0-06 exists.
- **Behaviour changes, deliberate:** `GET /api/user/subscription` used to answer 401 for *any* failure, including a Firestore error; now only a missing or invalid token is 401 and a real failure is a logged 500 (the thank-you page's polling already tolerates errors). Nothing else changed in what clients receive.
- **Tests:** `tests/auth.test.ts` (9): valid token, every malformed or invalid header, case-insensitive scheme, admin versus other user versus nobody, `isAdmin` with an unset or empty `ADMIN_UID`, the optional form, the old helper, and `route()` (passes arguments and responses through; an unexpected error is a logged 500 that leaks nothing). All 388 existing emulator tests pass unchanged, which is the regression check for the migration; production build compiles (Next checks the route export types).
- **Not done here (S5-05 / later):** `route()` is not yet on the other ~25 routes (admin, demo, contact, cron, webhook); they already use the shared guard and their own error handling, and moving them is mechanical follow-up.

## S5-06 · Translations loaded per language (2026-11-26, D16, STR-6)

**What changed.** The 218 KB `lib/i18n/index.tsx`, which held all six languages and shipped them to every visitor, is now one file per language in `lib/i18n/dictionaries/` (`en.ts` defines the `Translations` type, the other five are checked against it by the compiler). Which language to use is decided **on the server** (`lib/i18n/server.ts`): the `lang` cookie if valid, else the browser's `Accept-Language` (highest quality first, by primary subtag, so `de-AT` is German), else English (`lib/i18n/detect.ts`). The root layout renders `<html lang>` and the tab title in that language and hands that one dictionary to `LanguageProvider`, so there is **no flash of another language** (the first render already is the right one). `useLanguage()` is unchanged (`{ lang, t, toggle, setLanguage }`), so none of the ~40 components that use it changed.

Choosing another language loads only that dictionary (`lib/i18n/load.ts`, dynamic imports, latest choice wins if the visitor clicks fast), stores it in the `lang` cookie (a year, site-wide, `Secure` on https) and in `localStorage` (the account language sync still reads that), and updates the tab title and `<html lang>`. A visitor from before the cookie existed, whose choice is only in `localStorage`, is carried over once.

**Proof.**
- `npm run i18n:check` (in CI, before the tests) compares every language with English: same keys, no empty text, same `{placeholders}`; the same rules run in `tests/i18n-detect.test.ts` (11 tests, including Accept-Language ranking, q=0, wildcards, malformed headers, cookie precedence).
- Real browser (`scripts/verify/browser/i18n.cjs`, 20 checks, production build): a first visit with `de-DE` gets `<html lang="de">`, a German title and German text in the server HTML, **and no English or Greek dictionary anywhere in the page or its scripts**; nothing is stored until the visitor chooses; choosing Greek in the switcher fetches one new chunk, sets the cookie, retitles the tab, and a reload is served in Greek from the server; an unsupported browser language gives English; the cookie beats the browser; a junk cookie falls back to the browser; the legacy `localStorage` choice is adopted and becomes the cookie.
- Bundle: each language is its own chunk (en 10.4, de 10.9, nl 11.1, es 10.6, it 10.5, el 13.7 KB gzipped) and a visitor downloads one, instead of all six in the shared bundle.
- Gallery snapshot (33 steps) and signed-in dashboard snapshot (50 steps) are **byte-identical** to the pre-change baselines. 278 unit tests pass; lint stays at 13 warnings.

**Trade-off to know (D16).** Reading the cookie on the server makes every page dynamic: pages such as `/terms`, `/faq`, `/privacy`, `/contact` and the landing page are no longer prerendered as static files, so each view is a server render (a few ms of work; Vercel cost is small but not zero). The landing page's own caching comes back with S6-02 (public plans cached with a tag, language from the cookie). `/[lang]` static routes (the other D16 option) stay available if SEO per language matters later: search engines see only the language of their first request today (English unless they send another `Accept-Language`).

Not covered here: the in-app wording of the six languages is still the draft from S1/S2 awaiting native review (S2-04 and friends). `tests/*` compare dictionaries through `tests/helpers-dictionaries.ts`; the app itself never loads more than one.
