# Sprint 5 · evidence

## S5-04 · one shared auth layer and a `route()` wrapper (2026-11-26, STR-2)

- **`lib/server/auth.ts`** is now the only place in the app that calls `verifyIdToken`: `verifyBearer(req)` (the user or null, never throws; for routes where signing in is optional), `requireUser(req)` and `requireAdmin(req)` (a result you return from on failure: 401 `{ error: "Unauthorized" }`, or 403 for a signed-in non-admin), and `isAdmin(uid)`.
  The `Authorization` header is parsed strictly (`Bearer <token>`, scheme case-insensitive); before, anything with `Bearer ` stripped out of it counted, including a bare token.
- **The nine route-level copies are gone** (`user/delete`, `user/subscription`, `user/language`, `galleries`, `galleries/[id]`, `galleries/[id]/cover`, `galleries/[id]/photos`, `stripe/checkout`, `stripe/verify`), plus the optional-token copy in the selection route and the one in `lib/server/photo-access.ts`.
  `lib/firebase/admin-guard.ts` (`getUidFromRequest`, `isAdmin`, used by the other admin and user routes and mocked by several tests) is now a thin delegate, so those files did not need to change.
  **Done when: `grep -rn verifyIdToken app lib` finds exactly one line, in `lib/server/auth.ts`.**
- **`route(scope, handler)`** in `lib/server/http.ts`: wraps a handler so an unexpected error is logged (JSON line with scope and request id) and answered as a plain `{ error: "Internal error" }` 500, never a stack trace. Applied to all handlers of those ten route files. Handlers keep returning their own 400/401/404 as before.
  Request parsing stays with `parseJson` (S3-09) and auth with `requireUser`, rather than being hidden inside the wrapper, so each route reads top to bottom. The language route also moved to `parseJson`. Error monitoring (Sentry) hooks in at `route()` once S0-06 exists.
- **Behaviour changes, deliberate:** `GET /api/user/subscription` used to answer 401 for *any* failure, including a Firestore error; now only a missing or invalid token is 401 and a real failure is a logged 500 (the thank-you page's polling already tolerates errors). Nothing else changed in what clients receive.
- **Tests:** `tests/auth.test.ts` (9): valid token, every malformed or invalid header, case-insensitive scheme, admin versus other user versus nobody, `isAdmin` with an unset or empty `ADMIN_UID`, the optional form, the old helper, and `route()` (passes arguments and responses through; an unexpected error is a logged 500 that leaks nothing). All 388 existing emulator tests pass unchanged, which is the regression check for the migration; production build compiles (Next checks the route export types).
- **Not done here (S5-05 / later):** `route()` is not yet on the other ~25 routes (admin, demo, contact, cron, webhook); they already use the shared guard and their own error handling, and moving them is mechanical follow-up.

## S5-05 · collection names only in repositories; types match stored data (2026-11-26, STR-3)

- **`lib/server/repos/collections.ts`** is the only place that spells a Firestore collection name: `usersCol()`, `galleriesCol()`, `paymentsCol()`, `plansCol()`, `promoCodesCol()`, `demoGalleriesCol()`, `gallerySelectionsCol()`, `contactMessagesCol()`, `stripeEventsCol()`, `customerNoticesCol()`, `auditLogCol()`, `favoritesCol()` (legacy), plus `systemStateDoc(name)` for the cron bookkeeping documents and `siteSettingsDoc()`.
  Each takes an optional `Firestore` (use the one you hold, a transaction's or a test's) and otherwise the app's Admin SDK database. About 80 literal references in 44 files were replaced; the old per-file constants (`COLLECTION`, `PROMO_COLLECTION`, `SITE_SETTINGS_DOC`, `STATE`) are gone. Collection **names are unchanged** (a test pins them), so no data moves.
- **Types match what is stored.** `GalleryDoc` gained `passwordEnc`, `pwChangedAt` and nullable `password`/`passwordHash`; `UserDoc` gained `compGranted`, `subscriptionSource`, `promoCode`, `remindersSent` and an honest `createdAt` (a Firestore Timestamp or a number, as stored). `PaymentDoc` and `StripeEventDoc` already matched what the code writes.
- **The three `as unknown as GalleryDoc[]` casts are gone**: `ownerGalleryOf(doc)` and `newestFirst` in `lib/server/repos/galleries.ts` give owner and admin routes a properly typed `OwnerGallery` (`forOwner` is now generic over any object, with the one unavoidable cast contained in that function).
- **Guard:** `tests/repos.test.ts` (3, in CI) fails if a `.collection("…")`, `.doc("a/b")` or `collectionGroup(` literal appears anywhere in `app/`, `components/` or `lib/` outside `lib/server/repos/` (scripts and tests may use literals), if a stored-data type is cast with `as unknown as`, or if a collection name changes.
- **Scope, stated plainly:** this is the typed-accessor layer, which is what the done-when asks for. It is not a full set of per-entity repository *functions* (`findUserByStripeCustomer`, `listOpenPayments` ...); queries still live in the routes and billing modules, now written against the accessors. Those can be pulled into `lib/server/repos/*` one at a time as the admin rebuild (S7) needs them, without another sweep.
- `lib/firestore/*` (the browser-SDK layer; it cannot read these collections under the rules) is excluded from the guard; its dead leftovers are S5-11.
- Verification: production build compiles; lint 13 warnings; 226 unit and 388 emulator tests pass unchanged (they are the regression check for a change this wide).
