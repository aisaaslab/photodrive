## S6-02 (server rendering, in progress) · S6-07 Pricing · S6-08 FAQ and final CTA · S6-03 nav and footer (2026-11-26)

**Server rendering and the plan cache.** The page `/new-landing` is a server component: language from the cookie, plans from `getPublicPlans()` (`lib/server/public-plans.ts`, `unstable_cache` with tag `public-plans`, at most 5 minutes old). Every admin plan change (create, edit, quick toggle, delete) calls `expirePublicPlans()` (`revalidateTag(tag, { expire: 0 })`, never throws); a unit test pins the call count in both admin routes and the failure behaviour (an unreadable list gives the no-plans card, and a failed read is not cached). Prices are in the first HTML (checked). S6-02 stays open until the page is moved to `/` (S6-14) and an admin edit is seen on a preview.

**Pricing (S6-07).** `lib/shared/pricing.ts` (`buildTiers`, `discountPct`, `tierDiscount`, `pricingView`, `visibleTiers`, with 12 unit tests): monthly and yearly variants paired by name; the toggle appears only when both intervals exist, defaults to yearly and carries "Save 31%" (or "Save up to …" when savings differ; none when currencies differ); each plan in its own currency (`formatMoney`, en-US for English, D19). With no plans the page shows the features card and a button, never a price. The browser check seeds plans in the emulator and verifies: prices and the saving badge in the server HTML, toggle default and behaviour, `$99` next to `€99` (own currencies), "Most popular", each button to `/subscribe?plan=<id>`, "Save 31% vs monthly.", "no auto-renewal" and "Stripe" text, and the fallback without plans. **Design vs product, for the owner:** the design draws a Monthly and a Yearly card side by side with a toggle; the product has admin-managed plans, so the toggle switches which interval's plans are shown (as the current site does). With one plan of each interval you see one card at a time rather than both.

**FAQ and final CTA (S6-08).** Four real questions from the existing FAQ (the design's mock answers are not used) plus the billing question, which is new (it did not exist) and states the true billing model; first item open; "See all questions" links to `/faq`. The closing panel reuses the existing headline and subtitle. **Nav and footer (S6-03):** the nav and footer are outside `main` (landmarks checked: banner, one main, contentinfo); the footer has the original logo, tagline, three link columns and the language menu. Screen-reader and axe checks are part of S6-11, so S6-03 stays open.

Browser check now: 70+ checks in six languages at three widths, plus the plans variant (`WITH_PLANS=1`, see the README).
