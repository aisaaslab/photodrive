### Lint baseline and warnings policy

`npm run lint`: **0 errors, 13 warnings.** The warnings are existing code, not new:

| Count | Rule | Where it comes from |
|---|---|---|
| 6 | `react-hooks/set-state-in-effect` | React 19 compiler rule; code that behaves correctly |
| 4 | `react-hooks/refs` | same |
| 1 | `react-hooks/purity` (`Date.now()` read during render) | same |
| 2 | `react-hooks/exhaustive-deps` | missing effect dependencies |

`eslint.config.mjs` deliberately downgrades the three React 19 compiler rules to **warnings** so they stay visible without blocking. Policy:

1. **Errors fail CI.** Fix them.
2. **No new warnings.** CI runs `npm run lint -- --max-warnings 13`, so adding a warning fails the build. When you remove warnings, lower the number
   in `.github/workflows/ci.yml` in the same change.
3. Do not silence a warning with `eslint-disable` unless the code is demonstrably correct, and say why in a comment.
